Progress, working and transition states

How the agent’s work shows while it happens, and how a phone changes under someone’s thumb without startling them. Rule: never a spinner alone. Every “working” state names the step, shows elapsed time, and ends in a row someone can tap. Reduced-motion users get the same information with no animation.

Build gave up after 3 tries. Nothing changed on anyone’s phone. Village kept the failing test and will try a different approach tomorrow. What failed
Every fallback names what still works. The safe default (“don’t send”) is reached by the same timeline whether the fallback succeeds or not.
Timing rules. Working indicators appear after 300 ms, never sooner (no flicker). Elapsed time shows after 2 s. Anything over 8 s gets a “you can leave this page” line. Rows animate in once (200 ms slide, 0 for reduced motion). Patches to a visible app wait for idle (no touch for 1 s) or the toast tap. Countdown rings use the server timestamp, never the phone clock.
What is never shown. Raw model text while streaming. Percent confidence to people (only to the Control Room). Spinners without a step name. Red before the safe default has actually been applied. Any state the user cannot act on or wait out with a known end.
